# #24 每日变化备份、启动补做与保留七份

任务：[每日变化备份、启动补做与保留七份](https://github.com/xianpingduan/klbook/issues/24)。用户确认审查基线 `9d4a20f`，前置 #22、#23 已完成。延续已确认的公开 HTTP、浏览器、真实数据库和实际文件测试边界。

## 实现

- 按电脑本地日期检查资料及必要系统配置的变化；排除日常会话、短期授权及备份自身状态，比较基准来自成功快照。
- 启动检查错过的时机，仅补做当前一份；失败保留成功基准，一小时后重试，也支持现有手动入口。
- 新备份完整校验后保留最近七份受管理成功备份；清理核对身份、路径及文件，其他目录和额外文件保留，清理异常单独显示。
- 恢复副本和移动后的资料库暂停备份，家长配置独立目录后再启用，不清理原实例的备份。
- 管理后台展示自动检查状态、下一次检查、清理提示与成功备份位置；学习端没有新增入口。

## 验证进度

- 自动备份专项：有变化/无变化、登录不重复、隔离恢复登录及原图读取、九天轮换、无关文件保护、额外文件拒清理、损坏文件导致失败且保留成功基准、缺盘重试、跨日停机补做、恢复副本拒绝写原目录均通过。
- 真实自动备份子进程运行中终止，重新启动后中断任务明确失败、原成功备份仍可验证，并只补做一份。
- 原完整备份 API 回归 9/9；后台页面 Edge/Firefox/WebKit 专项 3/3；类型检查与构建通过。
- 完整 API 回归 **117/117** 通过；完整浏览器回归正在执行。审查及正式运行副本更新尚未完成，不据此关闭本项。
- 未实测填满真实磁盘或全机断电，不把可控日期、写入/校验失败或进程终止当作上述实机故障通过。

操作说明：[完整资料库备份与恢复](../runtime-backups.md)。当前正式服务仍运行 #23 版本；不能把工作区构建当作正式 Windows 服务已更新。
