# 完整资料库备份与恢复

对应 [手动完整备份 #23](https://github.com/xianpingduan/klbook/issues/23) 和 [每日变化备份 #24](https://github.com/xianpingduan/klbook/issues/24)。保存目录后启用每日变化检查，也可随时手动生成完整备份。

## 家长操作

1. 在家庭电脑创建独立目录，例如 `C:\ProgramData\klbook\backups`，或已有其他磁盘上的目录。目录须与资料、程序目录分开，不能相互包含；网络共享、目录联接和符号链接不接受。
2. “家长管理 → 资料库备份”填写**家庭电脑上的绝对路径**。手机填写的也是电脑路径，不是手机相册位置。保存后点“立即备份”。
3. 等待“备份已生成并通过完整性校验”，核对最近成功时间和路径；刷新及重新验证管理权限后仍可查询。

Windows 服务以 LocalService 运行，目标须允许该账号写入。保存目录会实际试写和检查可得空间；生成前再次检查容量并保留 64 MiB 余量。容量可能在生成期间改变，写入失败仍报告失败，不能把预估空间足够当作成功。

不假定家庭已有第二块磁盘；同盘副本不能应对整盘损坏。失败或中断不删除已有成功备份；未完成目录保留供排查，不计成功。修复后重新生成。

## 自动检查与最近七份

- 按**家庭电脑本地日期**运行：服务每分钟检查是否到期，首次配置目录后开始检查；之后在次日零点后首次运行的检查中判断变化。当天检查后发生的修改在次日检查时处理，紧急需要可点“立即备份”。
- 比较学习资料、原图引用、账号、管理配置、导入记录及必要系统文件与最近一次成功快照。日常登录、短期家长授权、备份任务状态和临时导入/导出保护记录不触发新备份。没有资料变化时只更新检查状态。
- 从旧版本升级时，先完整校验现有成功备份并建立比较基准；无法验证的旧备份不能作为基准。手动成功备份也更新基准，当天不再自动重复生成。
- 停机或休眠错过检查，下次服务启动时补做**当前状态的一份**。不会补造过去各天的快照。正在运行的备份不会重复启动。
- 失败不会推进成功比较基准，也不会清理旧成功备份。一小时后再次自动尝试；修复目标盘或权限后可直接点“立即备份”。中断任务在下次启动明确标为失败，并重新检查当前状态。
- 每份新备份全部生成并校验成功后，按成功时间保留最近 **7 份**（手动和自动一起计数）。仅清理当前运行实例记录并核对身份的备份；不按文件夹名字批量扫描删除。更换目录前由同一实例管理的备份也适用七份规则。
- 清理前检查备份的资料库身份、清单、文件与路径，拒绝目录链接、异库备份及额外文件。不删除无关目录或用户追加的文件。清理失败时后台单独提示，新备份仍有效，可能暂时多于七份；下次成功备份后重试清理。
- 开始删除旧备份前先持久记录其文件清单，并将它移出可恢复列表。文件占用或停机导致清理中断时，保留进度；解除占用后，下次成功备份会继续核对并清理剩余文件。最近七份完整备份不受影响。
- 后台可查看自动检查结果、下一次检查时间、失败原因、最近成功备份和现存成功备份的位置。检查与重试均要求电脑开机且服务运行。

## 备份内容

每份使用独立的 `klbook-backup-<UUID>` 目录：

| 位置 | 内容 |
| --- | --- |
| `data/family.sqlite` | 一致数据库快照：账号、稳定资料库身份、修订、导入来源/回执、管理配置、草稿、回收站、归档及识别更正 |
| `data/attachments/pages/…` | 快照中每个原始页的原图及预览，包括服务器草稿 |
| `system/service-credentials.key` | 原安装存在或已存供应商凭据时保存的配套密钥，与数据库分开 |
| `system/runtime/…` | 正式 Windows 安装的部署清单、服务 XML、Caddyfile、网关状态（包括证书私钥），不含程序及依赖 |
| `manifest.json`、`complete.json` | 格式版本、资料库身份、逐文件长度/SHA-256及清单摘要 |

备份目录在写入前限制权限。Windows 只允许执行账号、部署记录中的家庭电脑用户、SYSTEM 和管理员访问，子目录继承。这是依赖 Windows 目录权限保护的本地备份，**不是密码加密的分享文件**；复制到其他位置后需重新核对权限。整个备份不通过网页下载，也不能提交到 Git 或当作学习资料包分享。

供应商凭据仍以密文存于数据库，配套密钥单独保存。校验会解密检查可用性，不输出凭据、不请求供应商。原系统已无凭据时允许没有密钥文件。

SQLite 使用驱动备份 API。生成期间保护附件免于物理清理，题目删除仍可提交；快照及文件全部生成后核对哈希、数据库完整性、外键、附件引用和凭据，全部通过才记成功。中断的 running 记录在下次启动标为失败。

其他设备尚未上传内容、未确认的临时导入/导出文件、程序和 Windows 系统本身不在资料备份内。普通学习资料包只流转学习材料，不能恢复账号或运行配置。

## 校验及隔离恢复

恢复目标必须尚不存在，父目录须已创建；不会覆盖已有目录。只读备份介质可校验和恢复。

源码构建目录中：

```powershell
node .\dist\node\server\backup-cli.js verify --source '<完整备份目录>'
node .\dist\node\server\backup-cli.js restore --source '<完整备份目录>' --target '<新的绝对资料目录>' --with-system
```

独立运行副本更新后：

```powershell
& 'C:\ProgramData\klbook\service\bin\node.exe' `
  'C:\ProgramData\klbook\service\app\dist\node\server\backup-cli.js' `
  restore --source '<完整备份目录>' --target '<新的绝对资料目录>' --with-system
```

`--with-system` 明确允许恢复受保护配置：密钥放回新资料目录；运行配置保留于 `system-restore/runtime`，供维护时核对，不立即覆盖服务或信任根。新目录按执行恢复的用户限制权限。失败保留目标供检查，重试选择另一新目录；原资料及备份不变。

恢复工具在新目录写入恢复标记；恢复副本以及资料路径发生改变的实例会暂停自动备份和手动生成，避免对原运行实例的备份执行写入或轮换。需要启用时，在副本后台设置**与原备份目录分开的独立目录**。原备份历史不会被新实例接管清理。不要手动删除恢复标记以绕过这一检查。

用原版本或兼容的新版本程序，在不冲突的回环端口启动隔离副本：

```powershell
$env:KLBOOK_DATA_DIR = '<新的绝对资料目录>'
$env:KLBOOK_PORT = '18787'
$env:KLBOOK_REQUIRE_EXISTING = '1'
node .\dist\node\server\main.js
```

打开 `http://127.0.0.1:18787`，用原账号密码登录并验证家长权限。核对跨页、答案、共享原文、识别更正、学习阶段、草稿和回收站；重复导入原包应保留原跳过/冲突结果。恢复保留资料库身份与修订，验证期间不要把学习设备切到隔离副本。

确认后再安排正式切换：停止旧服务并保留回退副本；核对 `system-restore/runtime/deployment.json` 的路径、用户 SID、端口和地址，按 [Windows 服务说明](windows-service.md)重新准备匹配程序和权限。复用网关状态前核对原公开根摘要，不直接覆盖另一台电脑的服务配置。

## 验证边界

测试使用公开 HTTP、真实 SQLite、实际文件及恢复 CLI，覆盖复杂资料、账号权限、重复导入、配套密钥、目标离线、损坏文件、真实 Windows 拒写/联接、只读备份和进程中断。并发删除回归在移除附件保护后失败，恢复后通过。

自动调度另用可控日期验证有变化/无变化、跨日、停机补做、缺盘重试、文件校验失败、含图/无图资料库七份轮换与恢复副本隔离；真实测试子进程被终止后验证补做。从自动备份执行完整恢复、登录和原图读取。另覆盖恢复副本并发配置冲突，以及 Windows 文件占用导致部分清理、重启后续清理。

未实测填满真实磁盘或全机断电，不把预检及写入错误处理当作这些故障已完成实机演练。执行及部署状态见 [#23 验证记录](verification/issue-23.md) 和 [#24 验证记录](verification/issue-24.md)。
