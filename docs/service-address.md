# 配置和测试服务地址

对应 [#11](https://github.com/xianpingduan/klbook/issues/11)。只改变当前浏览器的资料请求目标，网页入口保持原地址；另一台设备继续使用自己的配置。

## 操作

首次连接、登录前和连接失败页都有“连接设置”；登录后从“我的 → 连接设置”进入。填写家庭电脑提供的基础地址，包含协议、IP或主机名，以及需要的端口。

1. 点击“测试连接”：只向目标的公开身份接口发出无应用凭据请求，检查是否为错题集及API版本是否兼容。不上传材料，也不取得登录或管理权限。
2. 测试通过后，点击“使用此地址并登录”：再次核对兼容性，保存目标，由家长登录该服务。即使此地址以前登录过，本次明确选择仍需重新登录。
3. 地址正确但暂时不可达时，可以点击“保存待连接地址”：单独保存在当前浏览器。原连接和资料保留；重新打开设置可继续测试，暂存地址不会自动成为业务请求目标。

格式错误不能保存，包括缺少协议、用户名密码、接口路径、查询参数、片段、无效端口等。家庭局域网使用HTTPS；HTTP只接受本机开发回环地址。手机的`localhost`和`127.0.0.1`指手机自己，不是家庭电脑。

## 跨来源部署

“网页来源”是浏览器地址栏中的协议、主机和端口；“服务地址”是题目及附件请求的目标。两者可以不同。目标电脑必须在`KLBOOK_ALLOWED_ORIGINS`中允许实际网页来源，并重启该目标应用服务。例如网页入口为`https://family-pc:8443`：

```powershell
$env:KLBOOK_ALLOWED_ORIGINS = 'https://family-pc:8443'
npm.cmd start
```

多个来源用逗号分隔，不能使用通配符替代核对。环境变量在目标电脑配置；在客户端填写服务地址不会修改后端监听、Windows防火墙、证书或服务器允许来源。登录、收集、管理请求和受保护附件均通过同一个已选目标发送。

前端入口和每个HTTPS服务都需使用设备信任、名称匹配的证书；浏览器要求本地网络访问权限时需按实际用途允许。连接失败时检查地址、电脑服务、证书、局域网权限和允许来源；浏览器网络错误本身无法可靠区分这些原因，不自动断言磁盘或账号故障。不通过关闭浏览器安全限制使连接成功。

## 本机保存与后续范围

网页配置按来源保存在当前浏览器。配置采用单条记录区分当前地址和待连接地址；确认新地址时清除待连接值。升级继续读取旧版`klbook.target`，已有设备凭据和材料暂存不迁移、不清空。存储失败如实显示错误，当前输入留在表单中。

每个API实例的目标固定，明确选用另一个目标后创建新实例，首次兼容性请求不带旧令牌、家长密码或材料。日常登录令牌仍按目标地址保存；材料暂存仍按已登录的资料库与账号归属隔离。

本项交付地址配置、兼容性测试和已实现业务访问。完整离线重开由#9继续交付；含未同步数量、在途请求暂停、同库别名核对、切回续传及迟到响应的完整切换流程由#12验收。当前已打开页面在后端不可达时仍能进入设置，但不承诺尚未缓存的网页能在服务停机后重新下载。
