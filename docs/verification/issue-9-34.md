# #9 自动草稿与 #34 A 布局验证

## 实施范围

用户要求按顺序实施 [#9](https://github.com/xianpingduan/klbook/issues/9) 和 [#34](https://github.com/xianpingduan/klbook/issues/34)。先提交离线与自动草稿基础，再集成已选定的 [A 设计](../design/collection-interaction.md)。

- 小型编辑日志同步保存字段、框选、材料关联、当前步骤、修订和未确认的请求；图片字节使用原 IndexedDB 平台存储。按资料库、账号隔离，每个编辑器保留自己的日志。日志模块统一格式校验和条件写入；编辑器与启动补传共用同一修订重放协议。
- 准备好的页面由 Service Worker 提供离线重开；只缓存公开页面资源，登录和业务资料仍通过账号作用域管理。未缓存图片显示读取失败，可重试。
- 离线选图可继续框题、填写和确认收集。联网并重新打开或刷新时先核对家庭资料库身份，上传原件，再重放原请求、提交较新的内容。未确认回执不推进修订，不标记已同步。
- 普通返回保留进度；正式收集、更正已收集题目、取消及撤销保持各自含义。取消前要求完整进度已同步，以保护可撤销内容。独立原文、答案和管理端仍保留各自的显式保存行为。
- A 布局隐藏主流程的手动“保存草稿”，折叠选填和复杂整理入口；底部主操作支持安全区与可视视口变化。详情统一编辑入口。
- 自动草稿不调用 OCR；下一步仍使用现有后台识别，不阻塞图片收集。验证仅使用隔离数据库和测试服务，没有调用家庭资料库中配置的供应商。

## 自动化证据

新增 `test/e2e/autosave.spec.ts`，使用真实隔离 SQLite、附件及浏览器存储，覆盖：

- 输入后立即刷新／返回、后退；草稿不自动计为已收集。
- 停服后重开既有草稿，离线新增图片，恢复后只收集一次，原件可取回。
- 保存回执丢失后重放旧请求再同步新填写；迟到回执不能把较新的输入标成已同步。
- 设备存储失败时提示并阻止无提示离开；恢复存储后继续。
- 已收集题目的未提交更正只在本机保留，显式保存才更新家庭资料库；离线刚确认收集后继续修改，也只补传已确认的快照。
- 其他设备取消旧草稿时，本机尚未同步的编辑保留；自动补传不会复活取消项，明确撤销后通过冲突核对保留新内容。
- 390、820、1440 像素布局、折叠默认状态、主按钮尺寸及滚动后可达性。

原有跨页、取消撤销、批量、共享原文、答案、服务地址、两设备冲突和管理权限测试按新入口执行。

### Standards

### Spec

初审发现 2 项 P1：离线确认收集后的未提交更正可能被补传；其他设备取消草稿可能删除本机尚未同步内容。先以真实浏览器和公开 API 复现，再修正提交快照与取消日志保留，新增对应回归。独立复审及实际 `FamilyApi` 重放检查确认两项均修复，未发现新的可行动问题。

自动化故障注入使用 Playwright 网络拦截；按[官方说明](https://playwright.dev/docs/api/class-page#page-route)阻止该组测试的 Service Worker，避免故障请求绕过拦截而使测试失真。真实停服、离线页面重开两项测试单独启用 Service Worker，并实际停止、恢复隔离服务，未用拦截替代离线页面验证。管理概览始终查询实时结果；读取失败不会将本机缓存总数当作服务端总数。

## 真机验收记录与待办

### iPhone 14 / iOS 16.3 确认页布局修复（2026-10-08）

用户在 Safari 默认 100% 缩放下报告：题目预览被挤窄，“调整题目范围”竖排并与学科提示、补充信息重叠。已接通页面不代表该设备验收通过。

原因是生产 CSS 的默认 Safari 16.4 目标把 `max-width` 媒体查询压缩为范围语法；iOS 16.3 忽略这些查询，手机继续使用双列网格。Safari 从 16.4 开始支持这类范围语法，见 [WebKit 发布说明](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/)。已在 `vite.config.mjs` 明确 CSS 兼容目标，保留其他浏览器目标，并输出 Safari / iOS 16.3 可读取的断点规则。这是样式兼容修复，不宣称已经验证该系统的全部功能。

- 修复前：真实页面加载生产 CSS，在 WebKit 中模拟忽略范围查询，复现同样的竖排及重叠，按钮宽度为 60 像素；正常 WebKit 不复现。
- 修复后：生产 CSS 不含范围查询。Edge、Firefox、WebKit 的原有 A 布局流程及新增兼容场景共 **6/6** 通过；覆盖 390、820、1440 像素布局、图片区与学科的位置、按钮宽度、横向溢出和保存。
- 类型检查、生产构建、`git diff --check` 通过。仅调整样式构建目标和浏览器回归，没有修改资料库、保存协议或识别配置。
- 本次模拟只覆盖旧版浏览器忽略范围查询的行为，不等同于旧 Safari 真机。
- **真机复测通过（2026-10-08）**：用户使用 iPhone 14、iOS 16.3、Safari 默认 100% 缩放，在收到刷新重开和布局核对步骤后反馈“验证后正常”。据此记录本次确认页竖排／重叠问题已修复；该反馈仅覆盖布局，不扩大为拍照、批量收集、离线、同步或键盘场景全部通过。
