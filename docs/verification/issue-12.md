# #12 切换服务时保护凭据和未同步资料

日期：2026-10-19。任务：[GitHub #12](https://github.com/xianpingduan/klbook/issues/12)。用户已确认审查基线 `bde4518`，包含此前尚未提交的 Safari 布局和批量提示修正。用户要求先实现；#9 的 iOS 停服与离线重开验收继续保留。

## 实现

- 打开连接设置后暂停原 API 实例、取消尚未完成的请求，并拒绝旧实例后续请求。启动过程的旧响应不会再发起补传，也不会切回旧页面。
- 按资料库和账号读取本机待上传图片与未同步／未提交题目整理数量。图片按操作编号去重；读取出错时明确提示并阻止启用新地址。首次身份检查仍在等待时也能读取本机数量。
- 新地址只做匿名兼容性检查，明确选用后由家长重新登录。使用认证响应中的稳定资料库及账号身份选择暂存，不凭地址或显示名称推断同库。
- 同库别名或新地址可以继续原有补传与上传队列；不同资料库保留各自凭据和暂存。已经确认收集与尚未提交更正仍按现有保存协议区分。
- 所有请求在读取响应正文后再次检查连接状态；旧目标的迟到结果不能更新新目标。服务器可能已保存的上传通过稳定操作编号安全重试。
- 新增目标最近一次认证的非秘密归属记录，只包含资料库与账号身份，用于退出／会话失效后的数量展示；不包含令牌，不授权读取或补传。旧版凭据在移除时也会保留归属。
- 无数据库结构、图片与编辑暂存格式或供应商配置迁移；仍使用原网页来源保存浏览器材料。操作见[服务地址](../service-address.md)。

定向 Edge 六个新增流程通过。测试先复现两个边界问题：迟到的旧 `/home` 仍启动上传；等待首次 `/info` 时设置显示零张。实现连接暂停和独立本机计数读取后复验通过。

类型检查、生产构建与 `git diff --check` 通过。完整 API **55/55** 通过。

完整三浏览器运行共 **210** 个场景，**202 通过、8 失败**；Edge、Firefox 各 70 项全部通过，8 项失败均发生在 WebKit。日志：`.scratch/issue-12/full-test.log`。失败分别处理如下：

- 5 个新增场景在选图控件仍禁用时直接设置文件，尚未进入上传流程。已让测试等待控件可用，再提交图片。
- 1 个设备测试因并行复现使用同一个输出目录，跟踪记录被清理，出现 ENOENT。后续运行均使用独立输出目录，设备流程复验通过。
- 2 个原有纸质答案／冲突用例发生操作等待超时，定向复验及各两次重复运行均通过，未再复现；没有修改对应生产代码或放宽断言。

修正后 WebKit 定向 21 项中 20 项通过，剩余迟到上传用例暴露测试拦截器转发 Blob 请求体不完整，服务器返回 422。现在只拦截一次，显式转发所选测试图片字节并确认服务器已接收，再延迟回执；切回后的补传走原生请求。该用例与上述两项答案操作各重复两次，共 **6/6** 通过。日志：`webkit-followup.log`、`webkit-confirmation.log`（同一目录）。

最终代码另执行 Edge／Firefox 登录、撤销与服务切换 **32/32**，WebKit 全部服务切换 **6/6**，均通过。日志：`auth-followup.log`、`switch-final.log`。完整运行和定向结果分别记录，不把定向通过记作一轮完整回归全部通过。

最终补强迟到响应场景：显式等待切回后的原生上传成功响应，并通过公开接口下载原图，与最初所选图片严格逐字节比较。两种迟到场景在三个浏览器共 **6/6** 通过，见 `replay-integrity.log`。这同时验证补传成功与原图完整，避免仅靠题数正确推断成功。

## 真机范围

本轮没有停止实际家庭服务，没有重建家庭资料库，也没有执行手机或平板的双目标切换。发现原预览未运行后，核对原数据库存在、端口空闲，已恢复应用和现有局域网网关；使用原公开根证书验证 HTTPS 身份及客户端资源成功，没有关闭证书校验。桌面 Edge、Firefox、WebKit 不能代替安卓 Chrome 或 iOS Safari 的 HTTPS 证书、局域网权限与离线存储验证。

实际验收时保持同一可信 HTTPS 网页入口，在有待上传材料时进入“我的 → 连接设置”，核对数量；分别登录隔离测试库和原库的新地址，检查另一库不收到材料、切回可继续且不重复。目标服务需允许该网页来源。#9 的 iPhone 14 / iOS 16.3 离线重开、停服恢复仍待验证，详见[#9/#34记录](issue-9-34.md)。

#12 实现与自动化已完成，保留开放并转为 `ready-for-human`，等待移动设备在可信 HTTPS 入口下的双目标切换验收；不改变 #9/#34 已记录的真机通过及待验范围。
