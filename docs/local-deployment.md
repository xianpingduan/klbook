# 本地部署与存储

## 已确认的方向

用户要求先将资料存储在本地电脑，所需中间件在本地安装。Q39 已确认第一版在家庭同一 Wi-Fi／局域网访问，使用统一资料库时电脑需要开机且服务运行。该决定替代此前以云端为主存储和托管的设想。

用户进一步要求“服务地址可在客户端进行配置”。客户端提供连接本地后端的地址设置，按设备保存；以下连接与切换规则为该需求的设计细化。

Q40、Q41 已确认：每天有资料变化时自动备份一次，保留最近 7 份成功备份、目录可配置；停机错过后下次启动补做一次。本地服务随电脑自动启动，并提供停止和重新启动的方法。

当前已完成基础技术选型和临时兼容性验证，尚无正式业务应用或安装脚本；本次没有安装常驻系统服务或调整系统网络配置。

用户随后确认最终需要 Android APK 与 iOS App Store 下载，目前无 Mac/开发者会员、先预留方案。移动端采用 Capacitor，页面随安装包提供，仍连接本地电脑后端；下文网页来源与浏览器暂存规则仅适用于网页端，原生权限、证书信任和存储另按 [移动交付计划](mobile-delivery.md) 验证。

## 组件与数据位置

| 部分 | 部署位置与职责 |
| --- | --- |
| 网页与后端 | 本地电脑；处理登录、收集、同步、查找、导入导出和后台服务管理 |
| 数据库 | 本地电脑；保存账号、当前学习阶段设置、题目及其学年／年级／学期、学科、来源、识别文字、引用、同步修订及回收站记录 |
| 附件目录 | 本地电脑的专用数据目录；保存原始图片、衍生图片、后续录音等实际文件 |
| HTTPS 访问入口 | 本地电脑；向手机、平板和电脑提供建议保持稳定的入口，客户端可配置连接地址，证书需被使用设备信任 |
| 设备暂存 | 当前手机、平板或电脑浏览器；暂存未上传材料与必要的离线页面，不作为统一资料库 |
| 外部能力调用 | 本地后端按三类独立配置调用；选外部供应商时仍需要互联网，结果存回本地 |

基础技术选型采用 SQLite 和本地附件目录，后端统一校验访问权限；这替代此前尚未锁定的 PostgreSQL 建议。单家庭、单台电脑场景减少一个独立数据库服务，代价是需要控制写事务和并发；详细理由及备份边界见 [ADR 0002](adr/0002-local-sqlite-storage.md) 和 [技术选型](technical-selection.md)。

所需中间件与运行时均在这台电脑上安装或运行，数据持久化目录与应用代码、临时文件分开。若采用容器，数据库与附件须映射到电脑的持久化目录，不能只留在可重建的容器层。首版依赖按实际需要列出，不预设额外缓存、消息队列或独立对象存储为必需组件。

## 局域网访问与离线行为

- 手机、平板访问电脑提供的应用入口，数据库与附件由后端读取，不让客户端直接连接数据库或共享磁盘。
- 入口地址建议保持稳定，实际后端地址可以在客户端修改；电脑接网线、移动设备接同一路由器 Wi-Fi 也属于可用部署方式，具体设备间可达性需要实测。
- 电脑关机、休眠、后端停止或离开家庭网络时，其他设备无法获取家庭资料库的最新内容。已缓存的页面和材料按实际可用范围显示；首次访问或未缓存内容不能承诺离线可用。
- 设备先成功在线访问并准备离线能力，才能在后续离线重开时继续处理本机暂存。恢复家庭网络连接并打开应用后补传；上传材料及记录都成功保存后，才标记为已同步。
- 仅断开互联网、局域网和本地服务正常时，本地账号登录、手动收集、查找与导入导出应继续工作；选用外部供应商的识别、转写和 AI 请求按不可用规则处理。
- 第一版不提供外网访问。局域网入口仍沿用家长账号、设备登录和管理验证规则。

网页内置相机所用的 `getUserMedia()`、以及支持离线页面的 Service Worker 均受安全上下文限制。手机访问电脑局域网地址不等同于访问手机自己的 `localhost`，因此部署需要可信的 HTTPS，不能只在电脑本机验证 HTTP 后就认定移动端拍照与离线能力可用。[MDN 相机 API](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[MDN Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)

## 客户端服务地址设置

### 配置与连接

- 当前客户端沿用网页应用方案。首次使用的连接页、登录页及设置页提供“服务地址”入口，家长完成配置；已缓存的客户端在后端不可达时仍能打开该设置，不要求先连接旧服务或通过旧服务验证才能改地址。
- 支持输入协议、IP 或主机名、端口组成的后端基础地址，例如 `https://192.168.1.10:8443`（示例，不代表已部署）。客户端统一据此访问登录、题目、附件、同步、导入导出和后台管理接口，不在各页面写死服务器地址。
- 默认可使用首次访问网页所对应的后端地址，允许修改。地址配置按当前设备的浏览器配置环境保存，重新打开后沿用；修改一台设备不改变其他设备，也不改变后端的实际监听地址。
- 提供“测试连接”，检查是否为兼容的错题集服务，并显示连接状态。测试不上传题目、图片或旧服务登录凭据；测试成功仅代表接口可达且兼容，后续仍需账号登录。
- 格式错误阻止保存；暂时不可达的有效地址可以保存为待连接配置。测试失败不清除原地址或本机资料，也不启动待同步任务。连接恢复后完成校验和登录，再启用业务请求。
- 状态区分待配置、待连接、已连接及版本不兼容；错误原因能确定时具体显示，浏览器只提供通用网络错误时提示检查网络、地址与部署配置，不猜测成密码错误。
- 地址设置只决定当前设备的连接目标；家庭资料访问、导入导出和服务管理仍由目标后端校验登录及管理权限。图片识别、语音转写、AI 供应商的接口和密钥继续在后台配置。

### 地址切换与暂存归属

- 应用新地址前暂停旧连接的新请求与自动重试，展示未同步资料数量；已发出的请求和迟到响应仍归属于原连接，不写入新资料库的界面或暂存区。
- 新目标先完成无凭据连接测试，再登录；旧地址的访问令牌或密码不自动发送到新地址。登录后核对稳定的家庭资料库标识及账号归属，不只根据 IP、名称或接口自报名称认定是同一资料库。
- 同一资料库仅更换地址时，核对成功后可以继续同步属于该账号的暂存；连接到其他资料库时，旧暂存与旧登录状态保持隔离，不自动转移、删除或上传。
- 支持改回原地址继续处理其暂存。跨资料库迁移沿用明确的导入导出流程，不能把修改服务地址当作迁移全部资料。

### 网页实现约束

网页入口与后端地址分别处理：已缓存的网页可在其原入口下修改后端地址；首次打开客户端仍需要一个可访问的网页入口。浏览器存储按来源隔离，直接改用另一个网页地址打开不能保证继承旧页面的配置与未同步资料。实施时应保留稳定的客户端入口，并验证断开旧后端后仍能打开已准备好的连接设置。[MDN 浏览器存储](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

当前设计优先使用同源部署；从已有网页连接不同主机或端口的后端时，目标后端必须允许实际客户端来源，并适配登录、附件和预检请求。HTTPS 页面不能依赖请求普通 HTTP 后端；证书信任、跨来源访问及实际浏览器的局域网访问要求属于部署验收，不能靠关闭浏览器限制实现。[MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)、[MDN 混合内容](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content)

## 开机自动启动

- 第一版本地后端及必要依赖随电脑启动，不要求孩子使用前在电脑上手动打开开发工具。
- 先确认数据库与文件目录可用，再让后端进入可服务状态；启动异常应有可查看的状态和错误记录。
- 在电脑上提供停止和重新启动服务的方法，即使网页后端已经停止也可操作。具体采用系统服务或其他适合本机的启动方式，在实施方案中固定。
- 自动启动不改变电脑的关机、休眠或网络可达条件，不包含修改系统休眠策略。

## 存储与备份

- 家庭资料库由数据库记录与附件共同组成。数据库保存稳定的附件标识和引用，不把某个设备的绝对磁盘路径作为资料包中的永久引用。
- 写入失败、磁盘空间不足或附件保存失败时保留可恢复的暂存，不把不完整资料标为已同步；删除共享材料仍需保护其他题目的引用。
- 30 天回收站在本地资料库执行。服务停止期间无法执行清理任务；重启后按原到期时间检查，界面不承诺关机期间准时清理。
- [资料包导入导出](import-export.md)用于学习资料恢复和迁移；其范围不等于整个运行环境备份。
- 整个服务的备份应覆盖一致的数据库快照及其附件，并单独保护必要系统配置。恢复验证要能还原原图、答案、共享材料及账号权限；外部密钥不进入普通学习资料包。
- 自动备份按已确认规则执行：每天检查资料是否较上次成功备份有变化，有变化时备份一次，保留最近 7 份成功备份；备份目录由家长配置。服务启动时检查是否错过应执行的备份，有需要则补做当前状态的一份备份，不伪造停机期间各天的历史快照。
- 完整生成并校验新备份成功后，才轮换超出保留数量的旧备份；失败或中断的备份不计入成功份数，不删除已有成功备份。仅轮换本应用在所配置目录中管理的备份文件。
- 备份覆盖一致的数据库状态及其引用附件，包括已落到服务器的归档信息、草稿和回收站记录；其他设备尚未上传的内容不在其中，系统配置按前述规则单独保护。
- 家长管理显示备份目录、最近成功时间与失败状态；目标盘未连接、不可写或容量不足时如实记录失败，修复后可重试，不将一次失败当作已完成备份。
- 建议将备份另存到已有的其他设备或移动硬盘，避免主资料和唯一备份同时依赖同一块磁盘。具体目标路径和容量在实施时核实，不推定已有第二块硬盘。

## 实施清单与验收

实施时提供适合目标电脑的组件版本、安装步骤、持久化目录、启动／停止方式、重启恢复方式、局域网入口与证书配置，以及备份恢复步骤。现有软件先核实并复用，避免覆盖已有数据库或其他项目配置。

1. 电脑与安卓、苹果设备在实际家庭网络通过同一入口登录，拍照、相册单选／多选和查看正常。
2. 设备 A 收集并同步后，设备 B 能看到相同资料；两台设备修改同一记录时不会静默丢失修改。
3. 断开互联网，本地登录与手动收集仍工作；外部服务失败不丢原图。
4. 关闭并恢复本地后端，客户端暂存和重试不产生重复题目，状态如实变化。
5. 重启数据库、应用及电脑后，资料与引用完整，本地服务随电脑自动启动；后端停止后仍能在电脑上通过所提供方法重新启动。
6. 通过资料包迁移到空资料库，以及通过运行备份恢复，分别核对各自承诺的恢复范围。
7. 两台设备可分别配置 IP／主机名和端口，重新打开后保持各自设置；实际登录、上传、查看附件和后台操作均使用配置的目标。
8. 旧后端不可达时，已准备离线能力的客户端仍可打开连接设置；测试失败保留原资料，服务版本不兼容时不启动同步。
9. 有未同步资料时分别验证同一资料库更换地址和切换到另一资料库，旧登录凭据不发送到新目标，资料归属与迟到响应处理正确。
10. 按日备份仅在资料有变化时产生新成功备份；停机错过后启动补做一次，失败不清理已有成功备份，成功后仅保留最近 7 份受管理备份。
11. 备份目录不可写或目标盘未连接时准确显示失败，恢复目标目录后可重试；恢复后的数据库、附件、账号权限和题目归档信息一致。

每月 50 元的运行服务预算继续保留；按实际外部能力用量重新估算，本地磁盘容量、备份空间和电耗单独记录。此前云托管价格研究仅作历史参考。
