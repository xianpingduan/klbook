# #12 切换服务时保护凭据和未同步资料

日期：2026-10-19。任务：[GitHub #12](https://github.com/xianpingduan/klbook/issues/12)。用户已确认审查基线 `bde4518`，包含此前尚未提交的 Safari 布局和批量提示修正。用户要求先实现；#9 的 iOS 停服与离线重开验收继续保留。

## 实现

- 打开连接设置后暂停原 API 实例、取消尚未完成的请求，并拒绝旧实例后续请求。启动过程的旧响应不会再发起补传，也不会切回旧页面。
- 按资料库和账号读取本机待上传图片与未同步／未提交题目整理数量。图片按操作编号去重；读取出错时明确提示并阻止启用新地址。首次身份检查仍在等待时也能读取本机数量。
- 新地址只做匿名兼容性检查，明确选用后由家长重新登录。使用认证响应中的稳定资料库及账号身份选择暂存，不凭地址或显示名称推断同库。
- 同库别名或新地址可以继续原有补传与上传队列；不同资料库保留各自凭据和暂存。已经确认收集与尚未提交更正仍按现有保存协议区分。
- 所有请求在读取响应正文后再次检查连接状态；旧目标的迟到结果不能更新新目标。服务器可能已保存的上传通过稳定操作编号安全重试。
- 无数据库结构、暂存格式或供应商配置迁移；仍使用原网页来源保存浏览器材料。操作见[服务地址](../service-address.md)。

## 验收覆盖

使用隔离真实 SQLite、实际图片和两个应用服务，通过浏览器及公开 API 检查。只有图片识别供应商使用测试替身，不调用家庭配置的真实识别服务。

| #12 条件 | 自动化证据 |
| --- | --- |
| 不可达时打开设置、显示数量并暂停旧连接 | 实际停止已准备入口的应用服务后刷新、新选图及确认收集；设置显示一张图片和一道未同步整理。延迟启动身份响应时，设置也能读取数量。 |
| 先匿名探测，再登录核对身份 | 监测目标 B 在登录前的请求仅为 `/info` 且没有应用令牌；A/B 使用相同账号名和学习者称呼、不同稳定身份，仍保持隔离。 |
| 同库续传、不同库隔离、切回处理 | A 的两张队列图片和未同步备注不会进入 B；A 的 localhost 别名登录后恢复队列与备注。A 停机后换新端口仍能补传原有已收集题目。 |
| 迟到响应不串库 | 分别延迟身份响应、登录态读取、已被服务器接收的上传回执和供应商识别完成；B 没有旧题或旧候选题。切回 A 找回材料和识别结果，手工学科保持且文字不被覆盖。 |
| 网页来源边界 | A 停机后保持原入口，分别连接 B 与新端口 A 并刷新；地址栏来源保持 A，配置页说明换来源不共享暂存。 |
| 重开、切回和续传不重复 | B 刷新后仍隔离，切回 A 后再次刷新，公开 API 只有一道题且原图可读。 |

## 真机范围

本轮没有停止实际家庭服务，没有重建家庭资料库，也没有执行手机或平板的双目标切换。桌面 Edge、Firefox、WebKit 不能代替安卓 Chrome 或 iOS Safari 的 HTTPS 证书、局域网权限与离线存储验证。

实际验收时保持同一可信 HTTPS 网页入口，在有待上传材料时进入“我的 → 连接设置”，核对数量；分别登录隔离测试库和原库的新地址，检查另一库不收到材料、切回可继续且不重复。目标服务需允许该网页来源。#9 的 iPhone 14 / iOS 16.3 离线重开、停服恢复仍待验证，详见[#9/#34记录](issue-9-34.md)。
