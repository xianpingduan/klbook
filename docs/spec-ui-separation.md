# 学习端与管理端独立布局规格

## Parent

[错题集收集版规格 #1](https://github.com/xianpingduan/klbook/issues/1)。本规格发布到已有[界面设计议题 #28](https://github.com/xianpingduan/klbook/issues/28)，是界面改造补充，保留父规格业务规则与现有任务范围。

## Problem Statement

学习者和家长目前共用页面外框，管理功能只是主页面内切换的面板。孩子日常收集受到账号、设备等信息干扰，家长在电脑上整理资料缺少稳定侧栏和表格空间；同一功能存在多个入口，难以形成使用习惯。

用户已经通过可点击 Demo 确认独立的两端风格，要求最大化精简入口，并在首页增加鼓励语。需要把设计接入真实家庭资料库，同时保留原图、草稿、设备暂存、来源管理与访问权限。

## Solution

在同一应用和家庭资料库中提供独立的学习端、管理端入口。学习端沿用浅色、柔和绿色、圆角卡片和大按钮；管理端采用蓝灰配色、侧栏、表格和表单。各设备都能使用学习端，设备尺寸不决定角色或权限。

学习端三个 Tab 各有固定职责：

- **首页**：标题、浅暖色鼓励语、已收集题目列表，点题目进入详情。鼓励语先使用本地固定文案“不会的题，可以慢慢弄懂。”“每一次认真回看，都是一点进步。”，无需外部服务。
- **收集**：手机和平板的拍照/相册入口，电脑的图片上传；集中处理本设备待上传批次及已保存的草稿。框题、确认、保存按步骤完成。
- **我的**：当前资料库与真实连接状态、家长管理入口、退出当前设备。后续服务地址设置沿用 #11/#12。

管理端先进入概览，只展示实际计数；通过侧栏进入错题资料、来源管理、设备与账号。错题资料页提供唯一上传入口，每条资料只有一个“打开”，在同一详情页查看和更正。原型中的示例数据、预览工具和模拟身份验证不进入正式界面。

## User Stories

1. 作为学习者，我希望打开原有网址就进入学习端，以便继续使用原来的登录和资料。
2. 作为家长，我希望能收藏独立管理入口，以便在电脑上直接进入管理流程。
3. 作为家长，我希望首次设置、登录和账号恢复完成后回到原本要访问的界面，以便不会迷路。
4. 作为学习者，我希望手机、平板和电脑都保持学习端身份，以便换设备也知道如何操作。
5. 作为学习者，我希望首页、收集和我的各有固定职责，以便不用在重复入口之间选择。
6. 作为学习者，我希望首页看到一句温和的鼓励，以便更愿意面对还没弄懂的题。
7. 作为学习者，我希望首页直接展示已收集题目，以便减少进入另一个错题本页面的步骤。
8. 作为学习者，我希望题目多时能继续加载，以便旧题不会因首页只展示一批而消失。
9. 作为学习者，我希望点开题目能查看完整原始页，以便核对图形、作答和批改。
10. 作为学习者，我希望可以补充学科、来源、页码、题号和备注，以便逐步整理而不增加首次收集负担。
11. 作为学习者，我希望仅在收集页选择拍照或相册，以便形成固定操作路径。
12. 作为电脑端学习者，我希望看到适合电脑的上传入口，以便不面对多个等价的文件选择按钮。
13. 作为学习者，我希望取消拍照或遇到相机不可用时还能选图，以便继续收集且不清空已有材料。
14. 作为学习者，我希望按框题、确认学科、保存的步骤操作，以便小屏幕也能看清题目和主要按钮。
15. 作为学习者，我希望批量图片显示进度、支持逐张继续和取消，以便少量多次完成整理。
16. 作为学习者，我希望能区分仅在本机的图片与电脑已保存的草稿，以便知道另一设备是否能看到。
17. 作为学习者，我希望所有待处理材料集中在收集页，以便不必在首页和我的之间找草稿。
18. 作为学习者，我希望服务断开时材料和填写内容保留，以便恢复连接后重试且不重复生成题目。
19. 作为学习者，我希望返回、切 Tab 或切端前明确处理未保存修改，以便不会无意丢失内容。
20. 作为学习者，我希望更正一道已收集题后仍保持原有身份与收集时间，以便不会变成新的草稿或重复题。
21. 作为家长，我希望管理入口要求再次验证身份，以便普通学习会话不能直接进入后台。
22. 作为家长，我希望概览显示真实的已收集数、草稿数、启用来源数和有效设备数，以便了解家庭资料状态。
23. 作为家长，我希望侧栏位置稳定、概览不重复堆放快捷入口，以便容易找到管理页面。
24. 作为家长，我希望通过表格打开和更正题目，以便用电脑协助整理，并能在学习端看到修改。
25. 作为家长，我希望在资料页上传材料并完成收集，以便协助孩子而不必切换到学习界面。
26. 作为家长，我希望独立维护来源并在学习端及时看到结果，以便来源名称一致且旧题归属不丢失。
27. 作为家长，我希望查看和撤销设备访问，以便失去使用权的设备不能继续读取资料。
28. 作为家长，我希望重新生成恢复码时仍遵守只显示一次和旧码失效规则，以便账号管理保持可靠。
29. 作为家长，我希望管理授权到期后锁定后台并保留允许保留的未提交表单，以便重新验证后继续操作。
30. 作为家长，我希望结束管理会撤销管理授权并返回学习端，以便孩子接手时不带有管理权限。
31. 作为家庭成员，我希望直接打开、刷新或返回页面时能正确恢复所在流程，以便新入口不破坏日常使用。
32. 作为家庭成员，我希望升级后原有会话、题目、图片、来源和本机待上传批次仍可用，以便无需重新收集。
33. 作为学习者，我希望手机按钮易点、键盘与底部导航不遮挡操作，以便能顺畅完成整理。
34. 作为家长，我希望真实设备验证结果逐设备记录，以便清楚新版在哪些设备上已验证。

## Implementation Decisions

### 既有基础与本次边界

- 延用现有 React、TypeScript、Vite、Fastify、SQLite 和附件目录，以及未来 Capacitor 的平台边界；本次不重新选技术栈，不新增云端主存储或外部能力。
- 学习端和管理端分别持有布局、导航和样式作用范围；复用家庭访问、公开 API、收集状态、原始页展示、框选、来源与设备暂存能力，避免复制两套保存逻辑。
- 不以布局改造为由新增业务数据表。管理概览优先组合现有题目列表总数、启用来源与有效设备数据；不得把首批最多 50 条的长度当成总数。本机未上传图片不计入服务端草稿数，读取失败显示不可用及重试，不伪装成 0。
- 首个实施任务负责在既有基础上确定路由处理、共享状态持有位置和样式隔离方式，记录理由、兼容性和限制；选择必须在依赖它的实现前明确，并通过真实登录及管理概览证明可运行。

### 入口与访问

- 学习端使用同站点 `/learn`，管理端使用同站点 `/admin`；原根入口进入学习端。具体子页面路径由首个实施任务统一，但应可直接打开、刷新、前进及后退。
- 保持现有网页协议、主机和端口，沿用既有凭据与暂存命名空间；不要求用户搬库或清除浏览器数据。
- 页面路径返回应用页面；不存在的 API、缺失静态资源及附件错误继续返回原有错误，不能被页面回退统一变成 HTML 成功响应。
- 未初始化时走家庭设置，未登录时走登录或恢复；保留允许的站内目标，完成后回到学习端或管理验证。目标不得是任意外部跳转。
- 未获得有效管理授权时显示验证页，不展示后台数据或发起管理写入。现有短期管理授权及绑定设备会话的服务端校验继续有效；普通学习收集和更正权限保持不变，不扩大为所有题目操作都要求家长授权。
- 管理页用一个“结束管理”操作撤销授权并返回学习端，避免两个效果相同的退出入口；未解锁的验证页可以直接返回学习端。撤销失败须可见，不能声称服务器已经撤销。

### 精简后的实际业务行为

- 首页鼓励语为不含按钮或跳转的普通展示区域，不依赖 AI、联网生成、打卡、排名或奖励计数。
- 首页及收集页的草稿列表分别沿用已收集/草稿查询和分页；同一列表内继续加载，不新增等价的“我的错题本/全部草稿”页面。
- 手机和平板选择拍照或相册；电脑提供一个图片上传入口。底层设备选择能力可以共用，但同一页面不同时摆放两个等价的相册/文件按钮；必要的拍照失败回退保留。
- 沿用现有图片格式、大小、像素与批次限制，方向校正和触控框选行为不退化。题目区与学科是完成收集条件；来源、页码、题号、备注继续选填。原型未展示页码不构成删掉正式字段的授权。
- 本机待上传批次和已保存到电脑的草稿在收集页明确分区、显示状态，各材料只有一个继续操作；上传、保存、更正后刷新相关列表和概览。
- 取消本机批次项不等于删除服务器草稿。上传响应不确定时保留稳定操作标识用于重试；服务器已接收的草稿继续可找回，不引入本次未实现的删除功能。
- 批次未完成时显示继续下一张及稍后继续的处理方式；保存成功与上传中、仅本机暂存、失败分别呈现。已收集题的更正保留其身份、收集时间与状态，不因返回或暂存降级为草稿。
- 后台资料表格按已收集/草稿分组并可继续读取，每行一个“打开”，详情和更正合并。后台上传复用现有采集规则、稳定操作标识与暂存隔离，不因来自后台生成第二份资料。
- 来源继续使用稳定身份，新增/改名/停用/启用均执行原授权、修订与幂等规则。返回学习端或恢复编辑时刷新来源；旧题保留已停用来源，但不供其他题目新选择。
- 设备撤销和恢复码轮换复用既有 API。撤销当前设备或恢复账号使相应旧会话失效，清理不再有效的管理视图；恢复码仍只显示一次且保存确认后才离开。

### 切换、授权与材料保护

- 共享状态在界面切换期间保存所属资料库、账号、批次、稳定操作标识和允许保留的表单；UI 卸载不得隐式删除材料。
- 未保存表单离开前给出继续编辑、保存后离开或明确放弃本次表单修改的处理。校验/保存失败留在原上下文；放弃表单不删除原题、原图或未上传批次。
- 站内导航和浏览器后退遵守上述保护。刷新/关闭页面用适用的浏览器离开提示；仅承诺已经持久保存的材料能恢复，不虚构所有未提交字段都已落盘。完整离线重开仍由 #9 承担。
- 管理授权到期或服务端拒绝授权时立即停止管理操作。允许保留的非敏感编辑内容与该家庭上下文绑定，重新验证后再继续；家长密码、管理令牌和恢复码不作为普通草稿持久保存。
- 设备会话失效、账号/资料库变化时不得把旧上下文的表单或图片发送到新上下文；保留旧暂存的隔离规则。完整目标地址切换仍由 #11/#12 承担。
- 手机主要触控区域以至少 48 CSS 像素为目标；主导航不遮挡内容，详情和编辑步骤收起 Tab。键盘打开后按钮仍可达；支持键盘焦点和控件名称。宽屏学习端仍使用学习导航，窄屏后台通过侧栏抽屉访问。

## Testing Decisions

延用用户已确认的测试边界：完整用户流程与公开接口，使用隔离的真实本地数据库和实际图片文件；不把组件内部状态或 CSS 类名作为功能正确的依据。界面布局以视口检查和实际设备结果补充。

- 家庭设置/登录/恢复、收集/批次续传、来源管理已有浏览器流程，沿相同入口补充新路由和两端操作。
- 权限、原图、稳定操作标识、修订和来源有现成公开 API 验证。通过实际持久化记录与另一设备读取证明保存、权限及重试行为，不以页面提示作为唯一证据。
- 管理到期沿用可控制的服务端时间与响应边界验证；不依赖长时间等待或仅隐藏按钮。
- 用改版前留下的数据库、附件、设备凭据和浏览器批次暂存验证原址升级；禁止在测试中先清空存储再声称升级兼容。
- 现有三个浏览器引擎继续覆盖主要流程；网页内置相机、证书信任、相册格式与触控仍需真实设备记录。旧版真机通过不能自动算作新版通过。
- 不增加外部服务调用；后续识别等服务仍按已批准方案在自动化中使用边界替身，并另行实测。

## Out of Scope

- 新的业务数据模型、分库、独立管理端部署、多家庭能力或账号角色重构。
- 搜索筛选、扩展学科及学习阶段、多页/共享阅读和答案关联、完整离线同步或冲突工作台。
- 图片识别、语音转写、AI 学习配置与调用，以及动态 AI 鼓励语、打卡奖励、复习与解题思路功能。
- 回收站、导入导出、备份与自启动等原有后续任务；未交付的功能不作为可用菜单展示。
- Android APK/iOS 构建与商店发布，继续由 #26 承接。此次界面可以复用，不代表安装包已交付。
