# 独立入口实施决定（#29）

## 选择及理由

沿用 React、TypeScript、Vite、Fastify、SQLite 和现有图片附件、平台适配。业务接口和设备凭据已经可以支持两个界面，本次无需新建数据库或部署第二个站点。

- **路由**：使用浏览器 History API 及有限页面表。学习端为 `/learn`、`/learn/collect`、`/learn/mine`；管理端为 `/admin`、`/admin/materials`、`/admin/sources`、`/admin/devices`。原根地址规范到 `/learn`。这些静态页面数量少，不需要新增路由依赖；与散落的 `parentOpen` 状态相比，地址可刷新、收藏和前进/后退。将来出现参数化详情路由时可在此边界引入路由库。
- **返回目标**：访问目标就是经过白名单匹配的站内路径，在初始化、登录和恢复码确认期间保留。忽略任意 `returnTo` 等查询参数，不接收外部跳转地址。服务端仅为这些页面返回应用入口，未知 API、附件和资源继续返回错误。
- **布局及样式**：一个稳定的内容挂载位置配合两套布局，学习端底部 Tab、管理端侧栏。样式限定于应用根及 `data-surface`，共享业务控件使用该界面的颜色变量；不复制业务组件。相比两个独立 React 根，这样能避免切端重新创建收集会话和图片队列。
- **状态**：设备访问会话位于 App；已登录工作区持有管理授权和已访问业务页面。管理授权仅在内存中，5 分钟到期隐藏并禁用后台业务区域，重新验证后恢复同一家庭的非敏感输入。身份变化卸载旧工作区；密码、管理令牌与恢复码不写入草稿或地址。
- **概览**：组合现有已收集/草稿列表的 `total`、启用来源和有效设备接口；按项呈现加载或失败状态，失败不能显示成零。本机图片不属于服务器草稿。进入概览、重新验证及主动刷新时更新。

## 兼容与限制

网页协议、主机、端口、资料目录、localStorage 凭据键及 IndexedDB 暂存结构不变。新增路径不会变更这些存储的来源。已有收集、原始页、来源和设备操作作为本轮中间版本继续可达，分别由 #30—#32 完成后续页面迁移。

未保存业务表单仅承诺同一工作区内保留；刷新/关闭不等于所有字段已保存。管理授权刷新后需要重新验证；完整离线恢复仍由 #9 负责。真实相机、证书、相册格式的新版设备结果需要另行记录。

## 验证边界

沿用已确认的公开 HTTP 接口和完整浏览器操作流程，使用隔离的真实 SQLite 与文件。检查直达、登录/恢复、后台授权、超一页统计、失败重试、原址升级、前进后退及窄屏/宽屏布局；不通过组件私有状态或 CSS 类名证明业务正确。
