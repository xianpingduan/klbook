# 两台设备修改同一份资料

对应 [#10](https://github.com/xianpingduan/klbook/issues/10)。学习端与管理端沿用各自布局，共用相同的冲突处理规则。

## 用户如何处理

保存时如果其他设备已更新这份资料，保留本页填写内容、图片与区域顺序，显示“当前版本”和“本次编辑”。可以核对学科、学习阶段、来源、页码、题号、备注，以及题目区、阅读材料关联和解答区；展开材料可查看图片。

- **保留本次编辑，继续核对**：只采用刚读取版本作为下一次保存的比较起点，保留本页字段。用户在编辑区合并需要的信息，再主动保存。它不会自动合并文字或区域，也不会立即写入。
- **放弃本次编辑，采用当前版本**：在本页采用资料库当前内容，放弃本次字段和区域修改，不删除原始图片或共享材料。
- **重新读取当前版本**：再次获取资料库内容，本次编辑不变。读取失败时禁止选择版本；恢复连接或重新验证后可以重试。

核对以后，其他设备仍可能再次修改；再次保存必须继续校验版本，不能以“已处理过冲突”为由强制覆盖。离开未保存编辑仍有确认；家长管理验证失效后，重新验证保留输入及核对状态。

## 覆盖范围

- 题目整理信息、学习阶段、题目区范围和顺序、阅读材料关联共用题目修订。
- 纸质答案修改也校验题目修订，但只写入解答区；核对后不会用旧备注或旧题干覆盖其他设备的更新。
- 共享阅读原文有独立修订；核对名称、范围和顺序后保存，所有引用该材料的小题继续共享同一份原文。
- 新建原文成功，但关联题目发生冲突时，明确显示“原文已保存，关联题目时发生冲突”。保留本次关联会打开基于当前版本的题目编辑页，仅预填刚保存的原文，用户确认后保存；不重复新建原文。

这里保留的是当前编辑页中的冲突输入。关闭或刷新页面后恢复完整未提交表单，以及离线重开与补传，由 #9 的设备暂存范围继续推进；当前已上传原件与既有追加图片暂存仍沿用原规则。家庭来源和默认学习阶段的管理配置已有修订保护，本任务不增加其逐字段合并界面。

## 写入约定

所有修改携带稳定 `operationId` 和 `expectedRevision`。服务端在同一事务内核对授权、已处理操作和记录修订；旧修订返回 HTTP 409，不写入。题目／答案的修订冲突包含 `conflict: { entity: "question", id }`，原文冲突包含 `conflict: { entity: "readingMaterial", id }`；调用方经原有鉴权读取当前记录后供用户核对。普通错误不携带该信息。

重复写入仍按既有契约返回当前记录，而不是历史快照。客户端必须先重放未收到回执的原操作；若返回修订已超过该操作预期，则进入核对流程，不能把后来修改误当成本次保存成功，也不能自动接着写入本页新编辑。

人工选择当前版本后，下一次保存生成新操作 ID，仍受同一修订检查。题目新建、答案和原文沿用稳定记录／区域身份，重复请求不额外创建题目、原文或区域。

本次不变更数据库结构与附件格式。后续新增题目修改入口应遵循相同约定，并验证并发写入、旧操作重放、处理期间再次更新以及权限拒绝。

验证记录见 [#10](verification/issue-10.md)。
