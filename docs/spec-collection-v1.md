# 错题集收集版规格：本地部署与多设备采集

整理日期：2026-09-17。测试方案确认及发布日期：2026-09-18。范围：第一版收集应用。状态：规格及测试方案已确认，已发布为 [GitHub Issue #1](https://github.com/xianpingduan/klbook/issues/1)，标签为 `ready-for-agent`。当前没有已实现的应用或已执行的功能测试。

## Problem Statement

一个家庭中目前就读小学四年级的孩子，希望自己整理语文、数学、英语、科学的错题。现有材料是带有批改和答案的纸质作业、试卷等，手写抄录效率低，题目、答案和原始材料容易分散，之后难以找回、复习或继续扩展。

长期目标是培养主动收集、总结、查漏补缺和探索解法的习惯。第一版优先解决“孩子能把纸质错题收进来、保存清楚、以后找得到”，降低输入负担，让原始材料和整理结果可以追溯。

使用地区为中国大陆，设备包括安卓与苹果手机、平板和电脑。家庭希望资料先保存在本地电脑，所需中间件在本地安装；各设备在同一家庭局域网访问，并能自行配置后端服务地址。

## Solution

提供适配手机、平板和电脑的网页应用，由本地电脑运行后端及所需中间件，并保存统一的家庭资料库。孩子日常进入收集和查找页面，家长管理账号、设备、服务配置、备份及资料导入导出。

最终交付目标已补充为 Android APK 安装和 iOS App Store 下载；采用共享 React 界面与 Capacitor 移动工程。用户目前没有 Mac 或 Apple Developer 会员，确认先预留发布方案；当前 24 项继续推进网页收集里程碑，移动安装、原生能力验证和上架另行跟踪，见 [移动安装与发布里程碑 #26](https://github.com/xianpingduan/klbook/issues/26)。

核心流程为：拍照或相册选图，电脑端对应上传图片；识别并提供候选题目；孩子点选错题、调整或补画边框；确认学科后保存；按学科、学习阶段、日期或来源找回。图片识别辅助选题与文字提取，保留原始页、图形、手写作答和老师批改。识别失败也能手动收集。

支持一页多题、一题多张有序图片、跨页题目，以及多个小题引用同一篇共享阅读材料。答案可从同页框选或另行拍摄，允许稍后补充；来源、页码、题号和备注选填。学科可扩展，学年、年级、学期从家长设置默认带入，允许更正并保留旧题的实际归属。

本地暂存、跨设备同步、30 天回收站、资料包导入导出和自动备份共同保护已收集内容。服务随电脑启动；手机和平板在电脑及服务可达时同步。三类外部能力——图片识别、语音转写、AI 学习——在后台分别配置、测试和启停，第一版孩子端使用图片识别。

第一版的结果应是孩子能独立完成收集、家长能管理和恢复资料的可运行应用。复习与掌握判断、语音总结、自己的解题思路、AI 教学和拓展练习安排在后续学习阶段。

## User Stories

### 采集与材料组织

1. 作为学习者，我希望用手机或平板拍照收集纸质材料，以便减少抄题时间。
2. 作为学习者，我希望从相册选择单张或多张图片，以便整理已经拍好的作业和试卷。
3. 作为学习者，我希望在电脑上上传图片，以便使用已有的材料文件。
4. 作为学习者，我希望批量选图后逐张处理，以便一次整理多个页面。
5. 作为学习者，我希望从同一张原始页收集多道独立错题，以便只保留需要整理的题目。
6. 作为学习者，我希望点选、调整或补画题目边框，以便把完整题干和图形收进来。
7. 作为学习者，我希望一道题能关联多张图片并调整顺序，以便完整保存跨页内容。
8. 作为学习者，我希望多个小题可以引用同一篇阅读材料，以便分别查找小题时仍能看懂题意。
9. 作为学习者，我希望随时回看原始页，以便追溯自己的作答和老师批改。
10. 作为学习者，我希望从同页选择答案或另拍答案页关联到题目，以便保存纸质解答依据。
11. 作为学习者，我希望先存题目、之后再补答案，以便不会因材料暂时不齐而中断收集。
12. 作为学习者，我希望来源、页码、题号和备注可以选填或后补，以便快速完成当天收集。
13. 作为学习者，我希望图形、表格和手写过程保留图片，以便文字识别没有覆盖的内容仍然可见。

### 图片识别与人工更正

14. 作为学习者，我希望识别印刷中文、英文、数字和数学公式，以便减少重复录入。
15. 作为学习者，我希望能修改识别文字，以便保存与原题一致的内容。
16. 作为学习者，我希望系统建议学科、题号和候选题目区域，以便更快完成归类与选题。
17. 作为学习者，我希望识别失败、未配置或停用时仍能手动框题并保存，以便继续收集。
18. 作为学习者，我希望保存原图不依赖识别结果，以便外部服务异常时材料不会丢失。
19. 作为学习者，我希望由自己确认哪些题需要收集，以便识别到的普通题目不会自动变成错题记录。
20. 作为学习者，我希望在需要时主动重试识别，以便以后补全结果并核对已有内容。

### 学科、学习阶段与查找

21. 作为学习者，我希望确认学科后就能保存题目，以便收集时不必先写错因总结。
22. 作为家长，我希望学科能在初始四科之外扩展，以便应用适应之后的学习需要。
23. 作为家长，我希望设置当前学年、年级和学期，以便新收集的题目默认带入归档信息。
24. 作为学习者，我希望能更正题目的学年、年级和学期，以便补收以前的材料。
25. 作为学习者，我希望升年级后旧题和已暂存草稿仍保留原归属，以便追溯不同阶段的学习材料。
26. 作为学习者，我希望尚未设置学习阶段时也能收集，以便配置不完整不会阻止保存。
27. 作为学习者，我希望按学科、学年、年级、学期、日期和来源查找，以便快速找回以前收集的题目。
28. 作为学习者，我希望在详情中看到题目、原始页、答案和相关阅读材料，以便完整理解这道题。
29. 作为学习者，我希望能补充和更正来源、备注及归档信息，以便逐步完善整理结果。

### 多设备、连接与暂存

30. 作为学习者，我希望手机、平板和电脑共用家庭资料库，以便换设备后继续整理。
31. 作为家长，我希望每台设备都能配置后端服务地址，以便连接本地电脑提供的服务。
32. 作为家长，我希望可以测试连接并查看状态，以便确认地址是否可用且服务兼容。
33. 作为家长，我希望未登录或旧后端不可达时仍能在已准备好的客户端修改地址，以便恢复连接。
34. 作为家长，我希望地址按设备保存，以便重新打开后沿用设置而不影响其他设备。
35. 作为学习者，我希望服务不可达时先保留本机暂存，以便稍后重新连接后继续处理。
36. 作为学习者，我希望准确看到仅本机保存、正在同步和已同步的区别，以便知道资料是否已进入家庭资料库。
37. 作为学习者，我希望恢复连接并打开应用后能够补传，以便断网或电脑重启不会造成重复收集。
38. 作为家长，我希望同一资料库换地址后可以核对身份并续传，以便地址变化不会丢失暂存。
39. 作为家长，我希望切换到其他资料库时隔离旧凭据和未同步资料，以便不会把内容传到错误位置。
40. 作为学习者，我希望互联网断开但家庭局域网正常时仍能登录、手动收集和查看，以便基础使用依赖本地服务即可完成。

### 家庭访问与管理

41. 作为家长，我希望通过账号和密码登录并管理常用设备，以便孩子日常使用简单且资料访问可控。
42. 作为学习者，我希望常用设备保持登录，以便进入应用后可以直接开始整理。
43. 作为家长，我希望导入、导出、删除和后台服务配置等操作需要管理验证，以便孩子页面不会获得管理权限。
44. 作为家长，我希望管理权限由后端检查，以便直接调用接口也不能绕过权限要求。
45. 作为家长，我希望两个设备修改同一记录时保留可处理的冲突信息，以便不会静默丢失修改。

### 三类能力的后台管理

46. 作为家长，我希望分别配置图片识别、语音转写和 AI 学习服务，以便按需要准备各类能力。
47. 作为家长，我希望为各类服务设置供应商、接口、地域、模型和凭据，以便接入适配的服务。
48. 作为家长，我希望保存配置与启用分开，以便准备配置时不会自动产生业务调用。
49. 作为家长，我希望分别测试三类服务并查看成功、失败和耗时，以便判断配置是否可用。
50. 作为家长，我希望三类服务独立启停，以便关闭 AI 学习服务时仍能使用图片识别。
51. 作为家长，我希望服务端在每次新调用前检查启用状态，以便旧页面也不能继续调用已停用服务。
52. 作为家长，我希望停用后保留已有资料和结果，并如实显示已发出请求的状态，以便了解实际处理进度。
53. 作为家长，我希望重新启用时不自动处理全部历史材料，以便控制调用范围和费用。
54. 作为家长，我希望密钥由服务端保管、界面只显示配置状态并允许替换，以便维护配置时不暴露已有凭据。
55. 作为家长，我希望查看分类用量、估算费用、错误摘要和配置变更，并设置调用额度，以便在家庭预算内管理服务。

### 删除、资料导入与导出

56. 作为家长，我希望删除的资料进入 30 天回收站，以便恢复误删内容或确认永久删除。
57. 作为家长，我希望删除某道题时保护其他题目仍引用的共享材料，以便资料关联保持完整。
58. 作为家长，我希望导出包含实际文件和整理信息的资料包，以便保留独立副本并迁移资料。
59. 作为家长，我希望导出前知道范围和未同步内容，以便清楚这份资料包实际包含什么。
60. 作为家长，我希望导入前预览新增、重复、冲突和学科对应关系，以便核对后再应用变更。
61. 作为家长，我希望重复导入同一内容时跳过已有记录，以便不产生重复题目或重复冲突副本。
62. 作为家长，我希望导入遇到修改冲突时保留当前版本，并能选择另存副本，以便不会覆盖已有整理成果。
63. 作为家长，我希望损坏、缺文件或不支持的资料包明确失败，以便现有资料不受影响。
64. 作为家长，我希望导入恢复图片、答案、共享材料、顺序、学科和学习阶段，以便完整保留整理结果。
65. 作为家长，我希望导入不重新识别、调用 AI 或改变服务开关，以便恢复资料不会触发额外处理。

### 本地运行与自动备份

66. 作为家长，我希望后端、数据库及所需中间件运行在本地电脑，以便家庭资料保存在自己的电脑上。
67. 作为学习者，我希望电脑开机后服务自动启动，以便使用手机或平板前无需手动启动后端。
68. 作为家长，我希望在电脑上能够停止和重新启动服务，以便后端不可用时也有维护入口。
69. 作为家长，我希望应用和电脑重启后资料仍完整，以便日常维护不影响已收集内容。
70. 作为家长，我希望每天有资料变化时自动备份一次，以便持续保留可恢复的资料库副本。
71. 作为家长，我希望配置备份目录并保留最近 7 份成功备份，以便控制备份位置和数量。
72. 作为家长，我希望停机错过备份后在下次启动补做一次，以便恢复运行后仍能保存当前资料。
73. 作为家长，我希望备份失败可见且不清理已有成功备份，以便及时修复问题并保留恢复能力。
74. 作为家长，我希望能够验证完整资料库备份的恢复结果，以便确认数据库、附件及管理权限确实可恢复。

## Implementation Decisions

本节归纳已确认的方向及现有设计中的行为约束。职责划分用于实施组织，不限定框架、代码布局或内部类结构；明确标为建议或待选的项目不视为用户已经锁定的技术选择。

### 1. 应用与部署边界

- 首版为响应式网页应用，面向一个家庭、一个真实学习者；适配安卓、苹果移动设备和电脑浏览器。
- 本地电脑运行网页、后端、数据库及所需中间件，数据库记录和附件共同构成家庭资料库。运行数据与代码、临时文件分开持久化。
- 首版通过家庭局域网访问，资料库电脑需要开机、服务运行且网络可达。互联网中断但局域网正常时，本地登录、手动收集、查看和资料导入导出应继续可用。
- 图片、录音等附件通过应用后端鉴权访问；客户端不直接访问数据库或磁盘共享。
- 部署须处理实际设备信任的 HTTPS、网页来源与后端来源、接口访问和附件加载。网页内置相机及离线重开能力按实际安卓、苹果设备验证。
- 基础技术方案已由 [任务 #2](https://github.com/xianpingduan/klbook/issues/2) 记录：React + TypeScript + Vite、Node.js + Fastify、SQLite 与本地附件、Windows 原生服务方向；移动端追加 Capacitor。已完成的是本机基础兼容性验证，业务应用、完整部署及原生安装包尚未完成。具体版本、运行参数和平台适配按实施记录及对应任务验证；此前 PostgreSQL 建议已由 SQLite 决定替代。
- 每月 50 元仍是运行服务预算约束，按本地部署与真实外部调用重新核算。硬件、容量及电耗单独记录；旧云托管与教学调用算例不作为本版成本承诺。

### 2. 逻辑模块与对外行为

| 模块 | 职责 | 可观察的操作与结果 |
| --- | --- | --- |
| 家庭访问与连接 | 本地账号、管理验证、设备登录、客户端地址及资料库身份 | 测试连接、登录、连接状态、切换目标、管理权限拒绝 |
| 错题收集与归档 | 原始页、候选题目、题目区、解答区、共享阅读材料、学科和学习阶段 | 导入图片、选题、更正识别、关联材料、保存、查询和补充信息 |
| 资料保存与同步 | 附件持久化、设备暂存、修订、重复请求与冲突、回收站 | 保存与同步状态、补传、恢复、删除及共享引用保护 |
| 能力管理与适配 | 三类服务的配置、测试、启停、实际供应商适配、用量和错误 | 分别测试与调用、状态变化、额度限制、无凭据明文的管理响应 |
| 资料包流转 | 一致导出、格式校验、导入预览、冲突与引用转换 | 生成自包含包、预览、确认导入、失败结果和可重复执行的导入 |
| 本地运行与备份 | 自动启动、电脑上的维护入口、日备份、保留规则与恢复步骤 | 启停、运行状态、成功备份、失败可见、从备份恢复资料库 |

逻辑接口统一使用记录标识、归属和必要修订信息传递关联；具体接口路由、字段命名与数据库定义在实现时形成一致契约。客户端各页面统一使用所配置的服务地址。

### 3. 数据模型与状态约束

| 概念 | 需要保留的内容与关系 |
| --- | --- |
| 家庭资料库与账号 | 稳定资料库身份、学习者归属、家长账号、设备会话与管理授权 |
| 原始页与附件 | 实际文件、完整性信息、来源，以及被题目区、解答区和阅读材料引用的关系 |
| 错题 | 稳定记录身份、修订信息、学科、独立的学年／年级／学期、收集日期、来源、页码、题号、备注 |
| 题目区与解答区 | 对应原始页、确认范围、关联题目和跨页顺序；答案允许为空及后补 |
| 共享阅读材料 | 阅读原文及其附件，与多个可独立作答的小题关联 |
| 识别结果 | 提取的文字与公式、建议区域、学科和题号建议，以及人工确认或修改后的内容 |
| 学科与当前学习阶段 | 可扩展学科列表，以及给新收集提供默认值的学年／年级／学期设置 |
| 设备暂存与同步信息 | 所属资料库及账号、本地记录身份、修订、上传状态和可恢复的待处理内容 |
| 删除与回收站 | 删除时间、恢复所需关联及到期状态，永久删除须保护仍被引用的材料 |
| 服务配置与调用记录 | 能力用途、适配器配置、受保护凭据、启用状态、额度、结果、用量和操作记录 |
| 导入批次与备份记录 | 格式版本、原始来源身份、冲突决策、完成状态、成功备份时间与完整性信息 |

以下状态分别管理，不使用一个“完成”字段混合表达：

- **收集状态**：草稿、已收集。确认题目范围与学科即可成为已收集；不要求答案、错因总结或解题思路。
- **同步状态**：仅在当前设备保存、正在同步、已同步。只有记录及其必需附件在家庭资料库完整保存后，才标为已同步；失败保留可重试内容和错误状态。
- **识别状态**：识别请求和结果独立于收集状态；未识别或识别失败的题仍可收集。
- **删除状态**：正常与回收站记录分别处理，不能把已删除内容当作未同步后自动恢复。

### 4. 原始材料、识别与保存

- 采用“以纸质原始材料为采集依据”的既有决定：原始图片始终可追溯，识别或重排不能覆盖唯一原图，图片保存不依赖识别成功。
- 拍照、相册单选／多选和电脑上传进入同一条收集流程。支持逐图处理、一页多题、跨页顺序和共享阅读材料。
- 识别生成可调整的候选题目与文字建议，由孩子选择真正需要收集的题。初始四科用真实材料评估，新增学科不自动继承相同识别质量承诺。
- 原始页中的图形、表格、手写与批改均保留图片依据；印刷中文、英文、数字和公式的文字结果可以修改。
- 对识别停用、未配置、失败或额度不足的情况，显示状态并允许手动框题、选学科和保存。之后可主动重试，不能静默覆盖人工修改。
- 附件写入不完整、磁盘不足或保存失败时，保持可恢复的暂存状态，不返回完整同步成功。

### 5. 学科、学习阶段与检索

- 2026-09-20 用户补充：来源通过下拉选择、可留空，由家长在独立来源管理中新增、改名、停用和启用。旧文字来源升级后保留；改名更新关联题目的显示，停用保留旧题归属。实施与验收由补充任务 [#27](https://github.com/xianpingduan/klbook/issues/27) 跟踪。

- 初始学科为语文、数学、英语、科学，以可扩展配置组织。新增学科后沿用收集、归档和查找流程，既有题目归属有效；管理入口细节属于实施任务。
- 家长设置当前学年、年级、学期，新建收集记录默认带入；每题单独保存实际归属，当前设置变化不修改旧题或已暂存草稿。
- 收集日期独立记录。补收旧材料时可更正学习阶段；尚未设置的归档字段保留为空或明确未设置，不阻挡收集。
- 首版落实学科、学年、年级、学期、收集时间和来源筛选，以及详情中的完整材料查看。
- 利用识别文字与人工更正内容作关键词查找是现有设计方向，具体检索字段和匹配方式留给实施方案，不将尚未确定的全文检索能力作为已验收承诺。

### 6. 家庭权限、服务地址与同步

- 家长使用本地账号和密码，负责首次登录及设备管理；孩子使用常用设备的日常会话。导入、导出、删除和服务配置等管理操作由后端验证权限。
- 账号初始化、恢复和会话管理在实施方案中明确；本版本地登录不依赖云端登录服务。
- 客户端连接设置接受后端基础地址，包含协议、主机或 IP、端口；按当前设备的浏览器环境保存。连接测试检查应用身份及版本兼容性，不发送学习材料或旧目标的登录凭据。
- 地址设置在首次连接、登录前和连接失败时可进入。已缓存客户端在后端不可达时仍可打开设置；首次使用仍需访问可用的网页入口。
- 格式错误阻止保存；有效但暂不可达的地址可以保留为待连接配置，失败不清除原地址或资料。连接成功不等于已登录或具有管理权限。
- 网页入口与后端地址分别处理。优先维持稳定客户端入口；不同网页来源的暂存不承诺自动共享。跨来源连接需在目标后端正确配置允许来源和登录、附件请求。
- 更换目标时先暂停旧连接的新请求与自动重试，显示未同步内容数量。旧请求的迟到响应仍属于原连接，不能写进新目标状态。
- 新地址先无凭据测试，再由家长登录并核对资料库身份和账号。核对为同一资料库后可续传，连接其他资料库时隔离旧暂存与凭据；支持切回处理旧资料。
- 补传和重复请求不能产生重复题目。两个设备修改同一记录时不得静默覆盖，需保留原修改并返回可处理的冲突；具体交互在实现中细化。
- 设备需成功访问并准备离线页面后，才承诺后续离线重开与本机暂存；未缓存的材料和未上传的其他设备内容不能宣称离线可见。

### 7. 三类外部服务

- 第一版后台完整提供图片识别、语音转写和 AI 学习的配置、测试、启用和停用。孩子端首版使用图片识别，后台开关不意味着后续学习页面已经实现。
- 三类能力按业务用途独立，即使使用同一供应商或视觉模型，也不能通过一个 AI 总开关一起控制。
- 各类配置支持名称、供应商、接口与地域、模型或服务标识、凭据、启停、超时、有限重试及额度。具体供应商需实际适配，不能只填写地址就声称兼容任意接口。
- 保存配置不调用外部能力；主动测试明确测试内容并计入用量。启用前检查必要配置，区分未配置、停用、启用可用和调用异常。
- 后端每次发起新业务调用及自动重试前检查开关和额度。停用不撤销已经发出的请求、不删除历史结果；对无法取消的请求如实显示状态。
- 重新启用不扫描历史资料。处理历史图片、录音或失败任务需要用户主动选择；未配置默认不产生外部请求。
- 密钥只由服务端保管和使用，管理界面显示配置状态或掩码并允许替换，不返回已有明文。孩子页面、日志和测试输出均不包含凭据。
- 配置变更记录操作人、时间及类型；调用记录按能力保存结果、耗时、可得用量和错误摘要。费用根据实际可得计量估算并标注性质，达到应用额度时停止新增付费业务请求。
- 本地保存不等于本地模型推理。选择外部供应商时，本地后端发送本次处理所需材料，结果保存回家庭资料库；本地模型接入仍需适配和效果验证。

### 8. 回收站、导出与导入

- 删除材料进入 30 天回收站，家长可恢复或确认永久删除；后端停止期间无法执行清理，重启后按原到期时间检查。删除仍被其他题目引用的原图或阅读材料时必须保护有效引用。
- 资料包包含实际文件及带格式版本的结构化信息，建议采用 ZIP 包装；不依赖会过期的下载地址，也不使用某台电脑的绝对磁盘路径作为永久关联。
- 首版默认导出当前账号在家庭资料库中已同步、未删除的已收集记录和全部必要引用材料。导出前展示数量及范围，提示当前设备未同步内容；草稿、回收站和其他设备未上传内容不在这份学习资料包内。
- 导出使用一致快照，保留原图、题目区与解答区范围、答案关系、共享阅读材料、图片顺序、识别与更正文字、学科、学习阶段、来源、备注和收集日期。
- 普通学习资料包不含账号密码、设备会话、供应商凭据或服务配置，不宣称是全账号或运行环境备份。
- 导入依次完成管理验证、文件选择、版本及完整性校验、预览、冲突与学科对应、确认应用、结果展示。校验不通过不写入现有资料。
- 同源同版本且内容相同的记录跳过；同一记录已有修改时默认保留当前版本，可将导入版本另存副本。副本保留来源，重复导入相同版本不继续生成副本。
- 回收站内的同一记录必须单独显示，由家长明确选择恢复；同名或未知学科提供对应建议，不仅凭名称自动合并。
- 导入在独立批次中完成校验和文件准备，完整后再使整批资料可见。中断、失败和重试不能留下半道题或重复记录；统一转换题目、答案、文件及共享材料引用。
- 保留原收集日期及题目归档信息，另记导入时间。支持的旧格式缺少学习阶段时保留未设置，不套用目标资料库当前设置，也不修改该设置。
- 导入不触发重新识别、转写或 AI 调用，不改变能力开关。其他应用及任意文档格式不视为可直接恢复的资料包。

### 9. 自动启动、备份和恢复

- 本地后端与必要依赖随电脑启动；先确认数据库及附件目录可用，再提供应用服务。电脑上提供独立于正在运行网页后端的停止、重新启动方法。
- 自动启动不包含自动修改休眠策略，也不意味着关机、休眠或网络不可达时仍可访问。
- 每天检查相对上次成功备份的资料变化，有变化时备份一次，保留最近 7 份成功备份，目录由家长配置。停机错过后下次启动补做当前状态的一份，不伪造历史快照。
- 自动运行备份覆盖一致的数据库状态及其引用附件，包括已落到服务器的草稿、回收站和归档记录；其他设备尚未上传内容不在其中。必要系统配置单独保护。
- 新备份完整生成并验证成功后，才清理本应用管理范围内超出保留数量的旧备份。失败或中断不计成功份数，也不删除已有成功备份。
- 后台显示备份目录、最近成功时间和失败状态。目标盘缺失、不可写或容量不足时明确失败，可在问题修复后重试。
- 资料包恢复和完整运行备份恢复分别验证各自范围。同一磁盘上的副本不能应对整盘损坏，独立副本位置按实际已有存储条件配置。

### 10. 实施交付约束

- 提供本机适用的组件版本、安装步骤、数据与备份目录、启动维护方式、局域网入口与证书配置、账号初始化与恢复、资料备份恢复步骤。
- 实施前核实已有环境并复用适用组件，不覆盖其他项目的数据库或服务配置。
- 第一版验收需有实际供应商适配及真实材料验证；模拟服务通过测试不能替代识别效果验证。没有生产凭据时明确报告该项未完成。
- 技术选型和配置细节由实施方案落实，不重新发起已经收口的产品范围访谈。原先面向习惯培养的首版表述按当前收集优先范围执行。

## Testing Decisions

### 已确认的测试边界与现有基础

当前仓库只有需求、领域词汇和设计记录，没有应用模块、测试框架或已有自动化测试可复用。现有先例是已整理的收集、服务管理、部署及导入导出验收场景；不能将这些文字场景视为已经运行通过的测试。

**以应用对外行为作为主要测试边界，已由用户确认：**通过浏览器和应用公开接口执行真实用户流程，使用隔离的真实数据库和附件目录；只在外部供应商边界提供可控测试替身。权限拒绝、重复提交、同步冲突等场景可直接调用同一组公开接口补充验证，不为每个内部类另建测试边界。

跨设备、操作系统启动和完整备份恢复需要补充实际部署演练；真实识别效果需要真实供应商和四科材料联调。这些验证与主要应用流程互补，不能仅凭模拟服务或桌面浏览器通过而宣称完成。

### 好测试的判断标准

- 从用户动作、公开响应和最终可读取结果验证行为；不依赖私有函数调用次数、数据库表名、内部类结构或组件层级。
- 保存后重开页面、从第二个会话读取、导出后在空资料库导入、备份后恢复到隔离环境，验证记录和实际附件都完整。
- 测试失败必须对应可解释的用户后果，例如原图丢失、误标同步、重复收题、答案错配、越权或覆盖旧资料。
- 自动化通过可控供应商响应重现超时、失败、格式异常和迟到结果；真实服务联调单独记录材料、结果与用量。
- 在隔离测试环境处理数据和时间条件，不操作家庭正式资料，不等待真实 30 天或连续运行 7 天才能验证到期及保留规则。
- 测试替身仅控制外部能力，不能用它替代需要验证的本地保存、权限判断、导入提交或备份恢复。

| T18 | 使用测试凭据读取前端响应、管理记录及运行日志 | 只显示配置状态或掩码，不暴露已有密钥；分类用量、错误与额度结果可核对 |
| T19 | 删除、恢复、到期清理及删除仍引用共享材料的题目 | 回收站规则有效，管理权限生效，其他题目仍能读取共享材料；到期清理在服务恢复后按原时间判断 |
| T20 | 导出含多页、答案、自定义学科和不同学习阶段的资料，在空库导入 | 原图、范围、顺序、所有关联和整理信息逐项一致，日期及学习阶段保留 |
| T21 | 查看导出范围，混合已收集、草稿、回收站和本机未同步内容 | 普通资料包只包含承诺范围及必需引用，不含凭据或会话，未同步提示与实际一致 |
| T22 | 重复导入；制造修改冲突、回收站记录和同名学科 | 未变记录跳过，副本不反复生成，冲突不静默覆盖，恢复和学科对应需要明确选择 |
| T23 | 导入损坏、缺文件、不兼容版本的包，或中断后重试 | 不修改原资料，不暴露半批记录，不重复入库；兼容旧格式缺字段时保留未设置 |
| T24 | 关闭三类外部服务后完成导入 | 恢复成功且没有识别、转写或 AI 请求，原服务开关保持原值 |
| T25 | 重启电脑及依赖，随后在电脑上停止和重新启动服务 | 服务自动启动且依赖就绪后可用，资料持续完整，后端停止时仍有电脑维护入口 |
| T26 | 推进按日备份条件，分别有变化、无变化、停机错过及备份失败 | 有变化才备份，启动补做当前一份；失败不计成功，不先删旧备份，成功后保留最近 7 份受管理备份 |
| T27 | 目标备份盘缺失、不可写或空间不足，然后修复并重试 | 状态准确，既有成功备份保留，修复后可产生有效备份 |
| T28 | 将完整运行备份恢复到隔离环境并登录查阅 | 数据库、实际附件、账号权限、服务器草稿、回收站与学习阶段一致，区别于学习资料包范围 |

### 真机与外部能力验证

- 在实际安卓、苹果手机和平板，以及电脑浏览器上检查拍照、相册单选／多选、方向、框选触控、HTTPS、连接设置及离线重开；记录实际系统和浏览器版本。
- 使用初始四科的真实纸质材料，覆盖印刷文字、英文、数字、公式、图形、表格、手写与批改交叠、密集排版及跨页；记录题目是否完整、建议是否需人工调整、文字更正量、失败情况与处理耗时。
- 不虚构识别准确率或统一耗时门槛。先记录真实结果，对影响“原题完整、能调整、能保存、能找回”的问题作交付缺陷处理。
- 对实际适配的三类服务分别完成后台功能测试。图片识别需连到收集主流程；语音转写和 AI 测试不要求提前实现孩子端学习页面。
- 使用实际家庭局域网检查第二设备访问、电脑重启及地址变化。明确哪些能力已验证，哪些因设备或生产凭据缺失尚未验证。

### 完成条件

第一版完成须满足本规格范围内的用户行为、关键验收场景和本地部署恢复要求；交付时附已运行检查、真实设备验证、外部服务结果及未完成项。通过文档校验、模拟服务测试或单机页面演示，均不能替代完整功能验收。

## Out of Scope

- 本版不交付复习队列、重做结果、暂时掌握、习惯统计、每日复习安排及相关激励页面。此前讨论的规则保留为后续方向。
- 本版不交付孩子端语音总结、自己的解题思路、AI 提示／讲解、拓展练习及家长核对拓展内容的学习流程；三类能力的后台配置、测试与启停属于本版。
- 自己的解题思路已明确列入后续方向，与错因总结分别保存；具体记录时机、文字／语音／手写照片交互、历史变化和 AI 辅助方式在该阶段细化，不作为收集完成条件。
- 不承诺自动判断整页哪些题做错、通用自动去笔迹、完美分题、全部手写内容准确转写、自动核定标准答案或无需人工更正。
- 不交付外网访问、云端主存储或云托管、多家庭运营或学校平台。Android APK 与 iOS App Store 交付已确认为后续里程碑，见下方“移动交付补充”；当前网页验收不覆盖安装包和商店发布。
- 不交付 PDF 打印题单或任意 PDF、Word、第三方错题软件资料包的结构化导入，也不承诺识别不同照片是否为语义上的同一道题。
- 不要求三类模型都在本机推理，不承诺任意供应商仅填地址即可接入。
- 不承诺首次未访问过的网页、未缓存内容或其他设备未上传资料能够离线获取，也不承诺电脑关闭时保持资料库在线。
- 不将普通学习资料包等同于整机或全账号备份；不将预算上限等同于已经完成成本核算或采购授权。

### 依据与优先级

本规格依据当前对话、《错题集收集版》《本地部署与存储》《后台服务管理》《资料导入与导出》、项目领域词汇表，以及“以纸质原始材料为采集依据”的既有设计决定整理。

采用用户最新选择：先侧重收集；本地电脑保存和安装中间件；家庭局域网访问；客户端服务地址可配置；首版三类服务后台管理、孩子端先用图片识别；资料导入导出；按日自动备份并保留最近 7 份成功备份；开机自动启动；学年、年级、学期归档。早期云存储设想和学习版的“首版”安排不覆盖这些最新决定。

需求已经收口，但实际代码、数据库、中间件、生产供应商配置和验收执行均尚未完成。本规格没有新增必须由用户决定的首版产品选择，也没有把已有技术建议伪装为已部署事实。

具体供应商、模型、接口版本、技术栈和部署参数由实施方案落定；实际凭据通过管理配置处理，不写入规格正文或普通学习资料包。
