- 后台保存回执丢失后另一设备继续修改：本机后续编辑和追加图片保留，旧操作重放不虚报成功。核对读取失败不能选择版本；管理授权撤销后重新验证，再读取、保存、重开成功。

## 完整回归与审查

构建与类型检查通过；完整 API 回归32/32通过。完整三浏览器回归运行129项，其中128项通过；Edge一项因测试进程监听随机端口`49666`返回`EACCES`而未进入用户流程，定向重跑通过。测试启动器对Windows随机端口的`listen EACCES`采用与端口占用相同的有界重选机制，明确指定端口仍直接报告失败。

补测发现：从关联冲突选择保留后，明确放弃待关联原文并进入答案页，返回题目仍会再次预填已放弃的选择。已先用测试复现，再在离开编辑页和切换入口时清除该待处理选择；最终冲突流程在Edge、Firefox、WebKit共9/9通过。

原129项浏览器场景均取得通过结果，不把首次完整运行记为全绿。证据：`.scratch/issue-10/full-regression`、`port-recheck`、`red-discard-link`、`final-conflicts`。

独立Standards初审无发现；Spec审查确认2项P2边界问题，均先通过公开浏览器流程复现再修复：

- 编辑原文时选择“保存后离开”，原文已保存但题目关联冲突，原实现仍执行待处理导航，掩盖冲突。现在关联完成结果明确传回编辑器，冲突时返回未完成并停在核对页。证据：`.scratch/issue-10/red-leave-conflict`；修复后冲突及原文流程三引擎15/15通过（`review-regression`）。
- 新建小题与原文更新同时发生，服务返回无题目目标的409；原实现误读临时题目身份，404后无法重试。现在只对明确的题目修订冲突读取当前版本，尚未创建成功时保留表单并继续使用原操作重试。测试向真实服务同时发出创建及原文修改，转交实际409响应，再检查重试成功且只新增一道题。证据：`.scratch/issue-10/red-create-conflict`。
