## 已完成的定向验证

- 双会话同时修改同一旧修订，只接受一个写入；另一方得到可定位的冲突。核对后新操作保存，迟到请求被拒绝，相同请求重复提交不多建题目，原件字节保持一致。
- 材料关系、题目区顺序及答案共用题目修订，原文独立修订；逐项核对处理后关联、顺序、原件仍可读取。
- 上述新增接口测试先在缺失结构化冲突信息处失败，实现后2/2通过。
- 浏览器双登录页面同时编辑：显示双方备注，保留本次编辑，核对期间再次发生并发修改仍拒绝覆盖；最终重开得到用户确认后的内容，仅一道题。
- 后台保存回执丢失后另一设备继续修改：本机后续编辑和追加图片保留，旧操作重放不虚报成功。核对读取失败不能选择版本；管理授权撤销后重新验证，再读取、保存、重开成功。
- 阅读原文可采用当前版本后再修改，答案可保留本次区域后保存；回执丢失重试不重复。原文已保存但题目关联冲突时，继续核对并关联，不覆盖他端最新备注，不重复建原文。
- 页面测试先在缺少核对入口与关联处理入口处失败，再实现通过。截图检查390px学习端及1440px管理端；保持独立布局。
- 新关联流程改变了旧原文测试的交互预期：从仅报错和留在原文表单，改为已保存原文及题目关联的核对页；仍检查他端解除关联未被覆盖。

## 完整回归与审查

构建与类型检查通过；完整 API 回归32/32通过。完整三浏览器回归运行129项，其中128项通过；Edge一项因测试进程监听随机端口`49666`返回`EACCES`而未进入用户流程，定向重跑通过。测试启动器对Windows随机端口的`listen EACCES`采用与端口占用相同的有界重选机制，明确指定端口仍直接报告失败。

补测发现：从关联冲突选择保留后，明确放弃待关联原文并进入答案页，返回题目仍会再次预填已放弃的选择。已先用测试复现，再在离开编辑页和切换入口时清除该待处理选择；最终冲突流程在Edge、Firefox、WebKit共9/9通过。

129项浏览器场景均取得通过结果，不把首次完整运行记为全绿。证据：`.scratch/issue-10/full-regression`、`port-recheck`、`red-discard-link`、`final-conflicts`。独立Standards／Spec审查尚未执行，等待用户确认已提出的`2fd8387`比较基线；本任务尚未宣告完成或关闭。
