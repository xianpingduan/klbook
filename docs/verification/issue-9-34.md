# #9 自动草稿与 #34 A 布局验证

## 实施范围

用户要求按顺序实施 [#9](https://github.com/xianpingduan/klbook/issues/9) 和 [#34](https://github.com/xianpingduan/klbook/issues/34)。先提交离线与自动草稿基础，再集成已选定的 [A 设计](../design/collection-interaction.md)。

- 小型编辑日志同步保存字段、框选、材料关联、当前步骤、修订和未确认的请求；图片字节使用原 IndexedDB 平台存储。按资料库、账号隔离，每个编辑器保留自己的日志。
- 准备好的页面由 Service Worker 提供离线重开；只缓存公开页面资源，登录和业务资料仍通过账号作用域管理。未缓存图片显示读取失败，可重试。
- 离线选图可继续框题、填写和确认收集。联网并重新打开或刷新时先核对家庭资料库身份，上传原件，再重放原请求、提交较新的内容。未确认回执不推进修订，不标记已同步。
- 普通返回保留进度；正式收集、更正已收集题目、取消及撤销保持各自含义。取消前要求完整进度已同步，以保护可撤销内容。独立原文、答案和管理端仍保留各自的显式保存行为。
- A 布局隐藏主流程的手动“保存草稿”，折叠选填和复杂整理入口；底部主操作支持安全区与可视视口变化。详情统一编辑入口。
- 自动草稿不调用 OCR；下一步仍使用现有后台识别，不阻塞图片收集。验证仅使用隔离数据库和测试服务，没有调用家庭资料库中配置的供应商。

## 自动化证据

新增 `test/e2e/autosave.spec.ts`，使用真实隔离 SQLite、附件及浏览器存储，覆盖：

- 输入后立即刷新／返回、后退；草稿不自动计为已收集。
- 停服后重开既有草稿，离线新增图片，恢复后只收集一次，原件可取回。
- 保存回执丢失后重放旧请求再同步新填写；迟到回执不能把较新的输入标成已同步。
- 设备存储失败时提示并阻止无提示离开；恢复存储后继续。
- 已收集题目的未提交更正只在本机保留，显式保存才更新家庭资料库。
- 390、820、1440 像素布局、折叠默认状态、主按钮尺寸及滚动后可达性。

原有跨页、取消撤销、批量、共享原文、答案、服务地址、两设备冲突和管理权限测试按新入口执行。类型检查及生产构建通过；完整 API **55/55** 通过（`.scratch/interaction-api-tests.log`）。完整浏览器回归和最终审查结果待本轮完成后记录。

## 真机待验收

本轮自动化不作为安卓或 iOS 真机结论。既往小米 14 的测试也不覆盖本轮新增能力。

1. 在家庭 Wi-Fi 的可信 HTTPS 入口在线登录；到“我的”确认“已准备离线页面”。
2. 从相册选一张测试图，框题并选学科，输入备注；直接返回和刷新后继续，确认内容完整。
3. 电脑停服后，重开同一入口，新增测试图并框题、确认收集；应提示本机保留或待同步。
4. 恢复电脑服务，重新打开应用；电脑确认只新增一题。再刷新一次，确认不重复且原图可查看。
5. 手机键盘打开时，展开补充信息填写，检查底部保存按钮和最后一项不被遮住。核对拍照方向、触控框题与系统相册。
6. 安卓 Chrome 和 iOS Safari 分别记录设备、系统、浏览器版本及结果；iOS 未提供资源时保持待验证。

首次离线访问、过期／已失效设备登录、未缓存图片不承诺可用。更新应用后需关闭旧标签再重开，让新的离线页面版本接管；浏览器清理站点数据会移除本机暂存。真实移动安装包仍由移动交付任务跟踪。
