## 实现与验证范围

电脑单张图片上传、题目区框选、初始四科选择、草稿继续整理、正式收集、选填信息更正、列表/详情/原始页追溯已经实现。公共接口及持久化协议见[手动收集设计](../manual-collection.md)。

| 验证内容 | 自动化证据 |
| --- | --- |
| 上传草稿、原件字节不变、鉴权、列表和详情、重复上传 | `test/api/collection.test.ts` |
| JPEG EXIF 方向、静态 WebP、真实格式识别、损坏/不支持/超限拒绝 | 同上 |
| 并发同操作上传只创建一道题，不同内容不能复用操作 ID | 同上 |
| 实际目录不可写入及附件缺失时无半成品发布，恢复后重试 | 同上 |
| 选填信息留空和补充、收集日期不变、修订冲突、第二会话及数据库重开 | 同上 |
| 文件选择、鼠标框题、草稿保存后重开、正式收集、补充和刷新找回 | `test/e2e/collection.spec.ts` |
| 实际 Node 进程重启后读题，独立浏览器会话查看原始页 | 同上 |
| 文件写入失败后刷新恢复待传图片；真实写入后丢弃响应，再次上传/保存不重复建题 | 同上 |

使用真实隔离 SQLite、文件目录、HTTP 进程及浏览器 IndexedDB。故障通过实际占用文件目录、暂移附件，以及让真实 HTTP 请求完成后丢弃响应产生；没有替换业务存储实现。图片素材由项目 SVG 样本生成 PNG/JPEG/WebP，包含图形、表格、模拟作答和红色批改；不是实拍学生试卷。

手动正常流程阻断浏览器全部非回环请求，后端没有调用识别或其他外部供应商。此证据不冒充真实路由器断网。目录写入故障已实测；没有填满物理磁盘或进行操作系统突然断电试验。
